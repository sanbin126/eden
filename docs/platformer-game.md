# 横屏平台跳跃小游戏实现方案（第一阶段 + 第二阶段）

## Context

Eden 现有小游戏（五子棋 / 扫雷 / 象棋）都是 Android 原生棋盘类。新增一款**横屏 2D 平台跳跃**小游戏，先做第一阶段原型：左右移动、跳跃、吃金币、到达终点。本阶段不做战斗、剧情、材料掉落、存档。

核心目标是**手感**（加速度、土狼时间、跳跃缓冲、可变跳跃高度）、**碰撞可靠**（不穿墙、不卡死）、**桌面与手机横屏双端可玩**。

产物是一套纯前端静态页面（Canvas 2D），独立文件夹，可直接双击 `index.html` 运行，后续再考虑接入 App（WebView）。

### 第一阶段明确不做

- 敌人 / 攻击 / 血量
- 剧情、对话、材料、背包
- 存档、关卡选择、多关卡
- 音效与背景音乐
- 美术资源替换（全部 Canvas 图形占位）

## 架构设计

`game.js` 内部按职责分块，全部用 ES2020 原生语法，不引入构建工具：

| 模块 | 职责 |
|---|---|
| `CONFIG` | 逻辑分辨率、物理常数、时间窗口等集中常量 |
| `Input` | 键盘 / 指针事件 → 统一的 `left/right/jump` 状态，含跳跃按下沿 |
| `Level` | 平台、金币、旗帜、出生点、关卡宽度的静态数据与重置 |
| `Player` | 位置、速度、状态（地面/空中/掉落）、物理更新 |
| `Physics` | AABB 分轴碰撞计算 |
| `Camera` | 横向跟随 + 关卡边界 clamp |
| `Renderer` | 背景视差、平台、金币、玩家、旗帜绘制 |
| `UI` | HUD 数字、通关遮罩、竖屏提示、重开 |
| `Game` | 固定步长主循环，串联以上模块 |

### 主循环

- **固定步长** `1/60s` + 累加器，渲染每帧一次（`requestAnimationFrame`），物理按固定 `dt` 更新，避免不同刷新率下手感不一致。
- 单帧最多补 5 步，防止切后台回来后瞬移。
- 所有时间窗口（土狼时间、跳跃缓冲）用秒为单位计时，与帧率解耦。

## 关键实现细节

### 1. 画布与高清屏

- 逻辑分辨率常量 `960 × 540`，所有游戏坐标都在此坐标系内。
- `canvas.width = 960 * dpr`、`canvas.height = 540 * dpr`，`ctx.setTransform(dpr,0,0,dpr,0,0)` 一次性缩放，逻辑代码不感知 dpr。
- CSS 用 `aspect-ratio: 16 / 9` + `max-width: 100%` + `max-height: 100%` 让画布在容器内等比缩放并居中；`image-rendering: auto`。
- 监听 `resize` / `orientationchange`，dpr 变化时重建变换矩阵。
- 手机上禁用页面滚动与缩放：`touch-action: none`、`overscroll-behavior: none`、`user-select: none`、`-webkit-tap-highlight-color: transparent`。

### 2. 横屏与竖屏提示

- 页面为深色全屏（`#0d1117` 系），游戏区居中。
- 通过 `matchMedia("(orientation: portrait)")` + 宽度判断：竖屏且宽度小于 900px 时显示覆盖层「请横屏游玩」，并用 CSS 隐藏 canvas 容器（不暂停逻辑，转回横屏即恢复）。
- 桌面浏览器不触发该提示。

### 3. 玩家物理参数（手感核心）

| 参数 | 值 | 说明 |
|---|---|---|
| `GRAVITY` | 2000 px/s² | 下落略快于上升，手感更利落 |
| `MAX_FALL` | 900 px/s | 终端速度，防穿透 |
| `MOVE_ACCEL` | 2400 px/s² | 地面加速度 |
| `AIR_ACCEL` | 1600 px/s² | 空中操控略弱 |
| `MAX_SPEED` | 330 px/s | 水平最大速度 |
| `GROUND_FRICTION` | 2600 px/s² | 松手后减速 |
| `AIR_DRAG` | 400 px/s² | 空中阻力 |
| `JUMP_VELOCITY` | -720 px/s | 起跳初速度 |
| `JUMP_CUT` | 0.45 | 提前松开时把 `vy` 乘以此系数（可变跳跃高度） |
| `COYOTE_TIME` | 0.10 s | 离开平台后仍可跳 |
| `JUMP_BUFFER` | 0.12 s | 落地前按跳，落地即跳 |

细节：

- `vy` 上升阶段用 `GRAVITY * 0.85`，下落阶段用 `GRAVITY * 1.25`，是"跳得干脆"的关键。
- 松开跳跃键时，若 `vy < 0` 则 `vy *= JUMP_CUT`，只削减一次。
- **土狼时间**：每帧在地面时重置 `coyote = COYOTE_TIME`，离地后按 dt 递减。
- **跳跃缓冲**：按下跳跃键时 `buffer = JUMP_BUFFER`；当 `buffer > 0 && coyote > 0` 时执行起跳，并同时清零两者，防止连跳。
- 玩家碰撞盒为 `28 × 40`，绘制为圆角矩形 + 简单眼睛，朝左朝右翻转。

### 4. 碰撞

- 平台是 AABB（`x, y, w, h`），玩家也是 AABB。
- **分轴解算**：先加 `vx` 移动 X 并解算 X 轴重叠（回退到贴边位置、`vx = 0`），再加 `vy` 移动 Y 并解算 Y 轴（落地时 `onGround = true`、`vy = 0`）。
- 单轴步进 + 速度上限 900px/s 且 60Hz，单步位移 ≤ 15px，远小于平台厚度，不会穿透。
- 落地判定：Y 轴解算时玩家从上方接触（`vy > 0`）才置 `onGround`；向上撞到平台底面则 `vy = 0` 并停止上升。
- 关卡左右边界：`x` 限制在 `[0, LEVEL_WIDTH - w]`，`vx` 清零。
- **掉出地图**：当 `y > 620`（逻辑坐标，画面下缘以下）时立即重生到出生点，速度归零，金币状态不变。
- 重生加一个 0.35s 的短暂闪烁提示（可选，仅视觉）。

### 5. 关卡设计

- 关卡宽度 `3000px`，逻辑高度 `540`，地面基准线 `y = 480`（地面平台顶面）。
- 平台数据为常量数组，`{x, y, w, h}`，地面段留 90~120px 的缺口，形成需要跳跃的段落。
- 浮空平台高度差控制在 90~130px（跳跃可达 ~130px），间距控制在 120~180px（可跨越）。
- 布局示意（从起点到终点）：

| 段落 | 内容 | 考验点 |
|---|---|---|
| 0 – 600 | 起始平地 + 2 个金币 | 熟悉走跳 |
| 600 – 1100 | 地面缺口 + 2 层浮空平台 | 连续跳跃 |
| 1100 – 1700 | 三段短平台，间隔递增 | 节奏控制 |
| 1700 – 2300 | 高台 + 低台组合 | 可变跳跃高度 |
| 2300 – 3000 | 落地平地 + 终点旗 | 冲刺收尾 |

- 金币 12 个，沿路径放在平台上方 40~70px 处，强制玩家在移动/跳跃路径上顺手吃到。

### 6. 金币

- 数据结构 `{x, y, collected}`，绘制半径 `10`，黄色圆形 + 内圈高光。
- 上下浮动：`drawY = y + sin(t * 3 + phase) * 4`，`phase` 由索引生成，避免同步摆动。
- 收集判定用 **圆 vs 玩家 AABB**（取最近点距离），比纯 AABB 更贴近视觉。
- 收集后 `collected = true`，不再绘制、不再判定，`coins++` 并更新 HUD。

### 7. 摄像机

- 目标位置：`targetX = player.x + player.w/2 - 960 * 0.4`（玩家偏左 40%，前方视野更多）。
- 平滑跟随：`camX += (targetX - camX) * min(1, dt * 8)`。
- 限制：`camX = clamp(camX, 0, LEVEL_WIDTH - 960)`。
- 只有横向滚动，纵向固定（关卡高度与逻辑高度一致）。
- 视差背景：远景山形/云层用 `camX * 0.3` 偏移绘制，增强纵深感（纯图形，无外部图片）。

### 8. 操作

**桌面：**

| 按键 | 行为 |
|---|---|
| `A` / `←` | 左移 |
| `D` / `→` | 右移 |
| `W` / `↑` / `空格` | 跳跃（按住更高） |
| `R` | 重新开始 |

- 监听 `keydown` / `keyup`，用 `e.code` 判断，避免输入法/大小写影响；对方向键与空格 `preventDefault()` 防页面滚动。
- 窗口失焦（`blur`）时清空所有按键状态，防"卡住一直跑"。

**手机横屏：**

- 左下角：左右两个圆形半透明按钮（`←` `→`），水平排列。
- 右下角：跳跃按钮（`JUMP`），直径略大。
- **多点触控**：使用 Pointer Events，记录 `pointerId → 按钮` 映射，`pointerdown` 置位、`pointerup` / `pointercancel` 清除。每个按钮独立 `pointerId`，可同时按住「右 + 跳」。
- 按钮容器设置 `touch-action: none`，按钮尺寸约 `72px` / `60px`，透明度 `0.28`，按下时 `0.5`，不遮挡主体画面（仅占两侧下角）。
- 触屏按钮与键盘输入合并为同一套 `left/right/jump` 状态，物理层不区分输入来源。
- 仅在检测到触摸设备（`matchMedia("(pointer: coarse)")`）时显示按钮，桌面隐藏。

### 9. HUD 与结束

- 左上角 HUD：金币图标 + `金币 3 / 12`；右侧小字提示 `A/D 或 ←/→ 移动 · 空格跳跃 · R 重开`（手机上隐藏键盘提示）。
- 到达终点：玩家 AABB 与旗帜碰撞盒相交 → `state = "cleared"`，玩家输入锁定，显示居中遮罩「通关！金币：X」+「重新开始」按钮。
- 重开：按 `R` 或点击按钮 → 重置玩家位置/速度、所有金币 `collected = false`、金币计数归零、摄像机归位、`state = "playing"`；关卡数据本身为只读常量，重建运行时状态即可。
- 通关后金币全部吃完额外显示一行小字「全收集！」（仅文案，不影响逻辑）。

### 10. 渲染顺序

1. 背景渐变（天空 + 远景视差）
2. 平台（带顶部亮边与投影，区分可站立面）
3. 金币（带浮动与光晕）
4. 终点旗帜（旗杆 + 飘动三角旗，`sin` 左右摆动）
5. 玩家
6. HUD（DOM，非 Canvas，便于响应式与按钮点击）

## 第二阶段：小怪与踩踏攻击

### 目标与范围

在第一阶段已跑通的代码上**增量修改**，不重写项目结构。新增：一种地面巡逻小怪、从上方踩踏击杀、侧面接触扣血、玩家 3 点生命与 HUD 血量显示。

**不做：** 连招、Boss、技能树、远程攻击、攻击按键、小怪种类扩展、掉落物。

**改动文件（不新增文件）：**

| 文件 | 改动 |
|---|---|
| `index.html` | HUD 内新增血量区域（3 颗心） |
| `style.css` | 心形图标样式、受伤时 HUD 抖动 |
| `game.js` | 小怪数据与巡逻、踩踏/受伤判定、生命与无敌、重置、渲染 |

### 数值设计

| 参数 | 值 | 说明 |
|---|---|---|
| `MAX_HP` | 3 | 初始与满血生命 |
| `ENEMY_W / ENEMY_H` | 32 × 32 | 红色方块占位 |
| `ENEMY_SPEED` | 70 px/s | 慢速巡逻，玩家有反应时间 |
| `STOMP_BOUNCE` | -520 px/s | 踩踏反弹，低于正常跳跃（-720），手感可控 |
| `STOMP_TOLERANCE` | 12 px | 判定"从上方落下"的容差 |
| `INVULN_TIME` | 1.2 s | 受伤后无敌时长 |
| `HIT_KNOCKBACK_X` | 260 px/s | 受击水平击退（背离小怪方向） |
| `HIT_KNOCKBACK_Y` | -300 px/s | 受击轻微上弹，便于脱离接触 |
| 闪烁频率 | 12 Hz | 无敌期间明暗交替 |

### 小怪数据与初始摆放

```js
// minX / maxX 为巡逻左右边界（世界坐标），不依赖平台边缘也限制活动范围
const ENEMY_DATA = [
  { x: 420,  y: 480 - 32, minX: 180,  maxX: 560 },   // 地面段 1（0–620）
  { x: 950,  y: 480 - 32, minX: 780,  maxX: 1180 },  // 地面段 2（740–1250）
  { x: 1650, y: 480 - 32, minX: 1440, maxX: 1840 },  // 地面段 3（1380–1900）
  { x: 2350, y: 480 - 32, minX: 2100, maxX: 2540 }   // 地面段 4（2020–2600）
];

// 运行时（可重置）
LEVEL.enemies = ENEMY_DATA.map((e, i) => ({
  x: e.x, y: e.y, w: 32, h: 32,
  dir: i % 2 === 0 ? 1 : -1,   // 初始朝向交替，画面更活
  alive: true,
  phase: i * 0.9,              // 呼吸动画错峰
  minX: e.minX, maxX: e.maxX   // 巡逻边界，重置时不改
}));
```

一段地面只放一只，避免两只小怪在同一平台互相穿过；终点段（2720–3000）不放，留出安全收尾区。

巡逻边界的作用：1 号小怪所在的地面段从 x=0 开始，只靠平台边缘反向会一路走到出生点（SPAWN.x=90），把站在起点不动的玩家撞掉血。因此给每只小怪设置 `minX/maxX`，让它在出生点右侧一段安全距离外折返。

### 巡逻与边缘检测

每帧（固定步长内）对小怪执行：

1. 计算候选位置 `nextX = x + dir * ENEMY_SPEED * dt`。
2. **巡逻边界**：`nextX < minX || nextX > maxX` → `dir *= -1` 并跳过本次移动。
3. **探地**：取前脚点 `footX = dir > 0 ? nextX + w + 2 : nextX - 2`，`footY = y + h + 2`；若该点不在任何平台矩形内 → 说明马上要掉下平台，`dir *= -1` 并跳过本次移动。
4. **撞墙**：候选位置与任一平台 AABB 相交 → 同样 `dir *= -1`，不移动。
5. 通过检测则 `x = clamp(nextX, 0, LEVEL_WIDTH - w)`。

补充规则：

- 小怪**不与玩家做物理推挤**，也不会被玩家顶开；只与平台交互。
- 小怪站在平台上（脚底 == 平台顶面）不算重叠，沿用第一阶段严格不等号的 AABB 判定。
- 小怪在 `game.state !== 'playing'` 时停止更新（通关后画面静止）。

### 踩踏与受伤判定

在 `update(dt)` 中，先更新玩家与小怪位置，再做一次相交检测（顺序：`updatePlayer` → `updateEnemies` → `updateEnemyHits` → `updateCoins` → `checkGoal`）。

为支持可靠的踩踏判定，在 `updatePlayer` 开头记录 `player.prevY = player.y`（移动前的值）。

```js
for (const e of LEVEL.enemies) {
  if (!e.alive || !overlaps(player, e)) continue;

  const prevBottom = player.prevY + player.h;
  const isStomp = player.vy > 0 && prevBottom <= e.y + STOMP_TOLERANCE;

  if (isStomp) {
    e.alive = false;
    player.vy = STOMP_BOUNCE;
    player.onGround = false;
    player.jumpCut = true;        // 避免反弹被误判成"松开跳跃键"而削减
    spawnEnemyBurst(e);
  } else if (player.invuln <= 0) {
    damagePlayer(e);
  }
}
```

**判定优先级说明：**

- 只要处于下落状态（`vy > 0`）且上一帧脚底还在小怪顶部之上（含 12px 容差），一律判定为踩踏，不扣血。
- 单步最大位移 ≤ 15px，配合 12px 容差不会出现"穿过去却没判定"的情况。
- 无敌期间仍可踩杀小怪，只是不再受伤。

`damagePlayer(e)`：

```js
game.hp -= 1;
player.invuln = INVULN_TIME;
player.vx = (player.x + player.w / 2 < e.x + e.w / 2 ? -1 : 1) * HIT_KNOCKBACK_X;
player.vy = HIT_KNOCKBACK_Y;
player.onGround = false;
player.jumpCut = true;
updateHud();                 // 血量图标即时刷新
if (game.hp <= 0) resetLevel();
```

- 同帧碰到两只小怪也只扣 1 点血（`invuln` 立即生效，后续循环直接跳过）。
- 击退不锁定输入，玩家仍可空中调整方向，避免"被击退进坑却无法自救"。

### 生命与重置规则（关键决策）

**选择：血量归零 → 整关重置。**

- 血量回满 3 点、金币计数清零、所有金币恢复、小怪全部复活、玩家回到起点、摄像机归位。
- 实现上直接复用现有 `restart()`（补充 `game.hp = MAX_HP`、小怪复活、清空 `invuln`），不新增 `dead` 状态，逻辑最简单。
- 理由：规则简单一致（生命耗尽 = 重开，与手动重开完全等价）、失败有成本，也避免"残血硬闯怪物区"的模糊状态。

**掉坑仍沿用第一阶段：** 只回起点，不扣血、不清金币、小怪不复活（`respawn()` 不变）。

> 备选（若后续觉得惩罚过重）：血量归零只重置生命与位置、保留金币。改动点仅为把 `resetLevel()` 换成"回血 + `respawn()`"，一行级别。

### HUD 血量

`index.html` 在金币胶囊中加入 3 颗心：

```html
<div class="hud__hp" id="hpHearts" aria-label="生命值">
  <i class="heart"></i><i class="heart"></i><i class="heart"></i>
</div>
```

### 数据模型（localStorage）

键：`eden.platformer.save.v1`（`SAVE_KEY`），版本号 `1`。

```js
{
  v: 1,
  coins: 0,                          // 累计金币（跨局累加，只增）
  materials: { tide: 0, star: 0, ember: 0 },   // 0 或 1，解锁卡片时 -1
  unlocked: { memory_tide: false, memory_star: false, memory_ember: false }
}
```

- **金币**：HUD 仍显示「本局金币 X / 12」；存档中的 `coins` 是累计金币，每次拾取 +1 并立即落盘。结算页同时展示本局与累计。
- **材料**：每种材料最多持有 1 个（`0/1`）。拾取时若已有则不再增加，但本局仍标记为已拾取（避免重复写入）。
- **剧情**：`unlocked[cardId]` 一旦为 `true` 永久保留；解锁时对应材料 `-1`。
- **本局状态**（`LEVEL.materials[i].collected`、`game.coins`、`game.runTime`）不落盘，重开即重置；存档只保存跨局资产。

### 模块职责与依赖方向

```
game.js (IIFE)
├─ save 模块：loadSave / sanitizeSave / persist       ← 只依赖 localStorage，不依赖游戏状态
├─ 关卡运行时 LEVEL.materials                          ← 只读 MATERIAL_DATA + 每局 collected 标记
├─ 拾取 updateMaterials() → save + toast + 粒子
├─ 结算 finish() → 读 game/save/LEVEL → 填 DOM
└─ 图鉴 openCodex/closeCodex/renderCodex/unlockCard → 读 save → 写 save → 重渲染
```

依赖方向单向：UI 层（DOM）只读游戏/存档状态；存档层不知道关卡与 UI；关卡层不直接写 localStorage（统一走 `persist()`）。

### 状态机与数据流

`game.state`：`playing | cleared | codex`，新增 `game.codexReturn`（`playing | cleared`）记录图鉴来源。

| 事件 | 前置状态 | 后置状态 | 副作用 |
|---|---|---|---|
| 玩家 AABB 碰旗帜 | playing | cleared | 锁输入、填结算、显示结算层；不写存档 |
| 点 HUD「剧情图鉴」 | playing | codex（return=playing） | 清空输入、暂停物理与计时（`runTime` 不再增长） |
| 点结算页「剧情图鉴」 | cleared | codex（return=cleared） | 结算层保持隐藏，关闭后回到 cleared |
| 点图鉴「关闭」 | codex | codexReturn | 恢复对应层；`accumulator = 0` 防补帧 |
| 点「解锁」且材料 ≥1 | codex | codex | 材料 -1、`unlocked=true`、落盘、重渲染卡片 |
| 点「解锁」材料不足 / 已解锁 | codex | codex | 直接返回，不写盘（幂等） |
| 重开（R / 结算按钮 / 血量归零） | 任意 | playing | 关图鉴与结算层、`runTime=0`、材料本局标记复位、存档不动 |

`runTime` 只在 `state === 'playing'` 时累加；图鉴暂停、结算停表。物理仍使用固定步长 `STEP`，切后台 `delta` 上限 `0.1s`。

**材料数据（世界坐标）**

```js
const MATERIAL_DATA = [
  { id: 'tide',  x: 375,  y: 280 },   // 平台 (300,380,110,20) 正上方 100px
  { id: 'star',  x: 1050, y: 160 },   // 平台 (1000,270,100,20) 正上方 110px
  { id: 'ember', x: 2440, y: 180 }    // 平台 (2380,290,120,20) 正上方 110px
];
```

- 三处都高于站立时的玩家顶部（玩家高 40，跳跃高度约 150），必须起跳才能碰到，属于「平台上方」支路。
- 材料判定沿用金币的 `circleHitsRect(半径 9, player)`，每局每材料只触发一次。
- 与金币水平间距 ≥ 45px，不会互相遮挡或误判。

### 失败语义表

| 情况 | 行为 | 幂等键 | 谁负责恢复 |
|---|---|---|---|
| localStorage 被禁用 / 抛 SecurityError | 降级为内存存档，游戏与图鉴继续可用；`console.warn` 带上下文，不静默 | 无（本次会话内 `save` 对象） | 玩家（换环境）或开发者 |
| 存档 JSON 解析失败 | 丢弃该存档、使用默认值，`console.warn`；不立即覆盖原键，直到下一次 `persist()` | `SAVE_KEY` + `v` | 玩家（重新收集） |
| 存档版本 `v !== 1` | 视为无效存档，使用默认值，`console.warn` | `SAVE_KEY` + `v` | 玩家 |
| 字段类型不合法（负数、字符串、缺字段） | `sanitizeSave` 逐字段归一：金币取非负整数，材料裁成 0/1，剧情只认真布尔 | 字段名 | 代码（下一次落盘纠正） |
| `setItem` 配额满 / QuotaExceededError | 保留内存存档，游戏继续；`console.warn`，不弹窗 | 无 | 玩家（清理空间后重新拾取） |
| 同一帧多次与同一材料相交 | `material.collected` 单次标记 + 库存上限 1，只结算一次 | `materialId` | 代码 |
| 重复点击解锁按钮 | `unlocked[cardId] === true` 直接 return；材料 <1 直接 return | `cardId` | 代码 |
| 图鉴打开时切后台 / 来电 | 保持 `codex`，`runTime` 不增长；回前台继续原状态 | `codexReturn` | 代码 |
| 通关后打开图鉴再关闭 | 回到 `cleared`，不重开关卡、不清结算内容 | `codexReturn` | 代码 |
| 图鉴内按 R / 跳跃键 | 键盘输入在 `state === 'codex'` 时整体忽略，不会误重开或误跳 | 状态判断 | 代码 |
| 移动端在图鉴列表里滑动 | 列表 `overflow-y:auto` + `touch-action: pan-y`，不触发轮盘/跳跃 | CSS 命中区域 | 玩家 |
